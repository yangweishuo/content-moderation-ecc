# 进化协议 (Evolution Protocol)

> Layer 5 核心文档，定义内容审核skill的自我进化规则、触发条件和执行流程。

---

## 一、进化原则

### 1.1 进化目标
- 降低误报率（False Positive Rate）
- 降低漏报率（False Negative Rate）
- 扩展检测覆盖范围
- 适应新平台规则和新法规
- 优化审核效率

### 1.2 进化约束
- 不得降低安全底线
- 不得违反法律法规
- 所有变更须可追溯（版本记录）
- 重大变更需人工确认

---

## 二、进化触发机制

### 2.1 自动触发

| 触发条件 | 进化动作 | 频率限制 |
|----------|----------|----------|
| 同一规则误报 ≥ 3次 | 降低该规则权重，添加例外条件 | 每天最多1次 |
| 同一规则漏报 ≥ 3次 | 提升该规则权重，扩展检测模式 | 每天最多1次 |
| 同一类型边界案例 ≥ 10例 | 分析模式，生成细化规则 | 每周最多1次 |
| 案例库新增案例 ≥ 50例 | 全量统计分析，生成优化建议 | 每周最多1次 |

### 2.2 手动触发

| 用户指令 | 进化动作 |
|----------|----------|
| "优化审核规则" | 全量进化评估 |
| "更新XX平台规则" | 更新特定平台知识库 |
| "学习新法规XX" | 解析新法规并融入知识库 |
| "调整规则敏感度" | 调整特定规则的检测阈值 |

---

## 三、进化执行流程

### 3.1 规则权重调整

```
触发 → 收集相关案例 → 分析误报/漏报模式
    → 计算权重调整量 → 生成变更提案
    → [人工确认] → 应用变更 → 记录进化日志
```

权重调整公式（参考）：
- 误报：`new_weight = old_weight × 0.7`
- 漏报：`new_weight = old_weight × 1.3`
- 权重范围：[0.1, 10.0]

### 3.2 新规则生成

```
触发 → 分析边界案例/漏报模式 → 提取共性特征
    → 生成候选规则（含检测模式、风险等级、依据）
    → [人工确认] → 固化到知识库 → 记录进化日志
```

### 3.3 知识库更新

```
触发 → 获取新法规/平台规则原文
    → 提取与内容审核相关的条款
    → 按现有模板格式化
    → 更新对应文件
    → 重新评估相关规则权重
    → 记录进化日志
```

## 四、版本管理

### 4.1 版本号规则

格式：`v{MAJOR}.{MINOR}.{PATCH}`

- **MAJOR**: 新增或移除整类规则（如新增AI内容审查类）
- **MINOR**: 新增单个规则或显著修改现有规则
- **PATCH**: 微调规则权重、修正描述错误

### 4.2 版本记录

每次进化记录以下信息：
```markdown
## vX.Y.Z - YYYY-MM-DD

**变更类型**: [规则新增/规则修改/权重调整/知识库更新]
**触发原因**: [自动触发条件/用户指令]
**变更内容**:
- 变更项1: <描述>
- 变更项2: <描述>
**影响评估**: [预期降低误报率X% / 预期覆盖Y场景]
**关联案例**: MOD-XXX, MOD-YYY
**确认状态**: [自动应用/人工已确认]
```

## 五、跨平台规则迁移

### 5.1 迁移逻辑

当平台A新增规则时，按以下逻辑评估是否迁移到平台B：

```
平台A新增规则 → 判断规则类型
    ├─ 法律强制型 → 同步到所有中国平台
    ├─ 平台特色型 → 仅保留在平台A
    ├─ 行业通用型 → 评估其他平台是否需要
    └─ 不确定 → 标记为"待评估"
```

### 5.2 迁移评估维度

| 维度 | 权重 | 说明 |
|------|------|------|
| 法规强制 | 最高 | 有法律法规要求的，必须同步 |
| 平台相似度 | 高 | 平台A和平台B的用户群、内容类型相似度 |
| 用户反馈 | 中 | 平台B用户是否反馈过类似问题 |
| 行业趋势 | 低 | 是否是行业普遍趋势 |

## 七、安全红线（不可进化项）

以下规则**不允许**通过进化降低权重或移除：

1. 危害国家安全的内容审核规则
2. 色情/儿童色情的检测规则
3. 恐怖主义/极端主义的检测规则
4. 法律明文规定的禁止性规则
5. 广告法第九条（绝对禁止情形）
